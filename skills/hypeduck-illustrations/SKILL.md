# HypeDuck 오리 일러스트

## Overview

글의 핵심 판단·구조·상태·은유 하나를 골라, 하입덕 노란 오리가 그 동작을 수행하는 16:9 손그림 해설 이미지로 만든다. 프롬프트 정본은 `PROMPT.md`에 있다 — 다른 일러스트 스킬의 프롬프트나 스타일 지시를 섞지 말고 이것만 쓴다.

스타일 고정값: 순백 배경 · 검정 세선 손그림 · 여백 40%+ · **오리만 컬러**(노랑 #FFD400 몸 + 주황 #FF8A00 부리, 얼굴은 CHARACTER 스펙으로 고정) · 한국어 손글씨 주석(빨강=경고/결과, 주황=흐름/화살표, 파랑=보조/상태) · 장당 메시지 1개.

## Workflow

1. **글 소화 → shot list.** 인지 앵커(판단·전환점·구조·전후 대비·상태)만 고른다. 본문 삽화는 4~8장, 단일 개념 요청은 1장. 균등 배분 금지 — 그림이 필요 없는 문단은 건너뛴다.
2. **장면 카드 작성.** 장마다 아래 5칸을 채운다(여러 장이면 이 형태로 나열):

```json
{
  "theme": "한 줄 주제 (영어)",
  "structure": "Before/after contrast | Character state | System | Concept metaphor | Filter metaphor | Hand-drawn chart",
  "core": "이 그림이 말하는 단 하나의 의미 (영어)",
  "composition": "장면 묘사 (영어) — The duck이 어디서 무엇을 하는지, 물건·흐름·크기 대비까지 구체적으로. 오리가 핵심 동작의 주체여야 함",
  "labels": "red handwritten \"주석1\" 위치 / blue handwritten \"주석2\" 위치 — 전부 한국어 2~4어절, 최대 4개"
}
```

3. **생성.** 프롬프트 정본은 같은 폴더의 `PROMPT.md`(CHARACTER + STYLE) — 고칠 일이 있으면 거기만 고친다. CHARACTER + 그 장의 5칸 + STYLE을 순서대로 이어붙여 16:9로 한 장씩 만든다. **CHARACTER 블록은 요약하지 말고 매번 통째로 넣는다** — 그게 오리 얼굴을 고정하는 유일한 장치다. `assets/hypeduck-logo.png`를 레퍼런스로 첨부할 수 있으면 첨부하면 더 확실하다(필수 아님). 이미지 생성 도구가 없는 환경이면 조립된 프롬프트를 장별로 출력하고 사용자가 쓰는 이미지 AI에 붙여넣으라고 안내한다 — 멈추지 않는다.
4. **QA — 전 장 Read로 육안 검사:** ① 순백 배경 ② 오리가 핵심 동작 수행(장식이면 실패) ③ 한글 주석 철자 정확 ④ PPT 인포그래픽 느낌 아님 ⑤ 여백 충분(육안 판정 — 경계선이면 통과, 주체가 화면을 꽉 채울 때만 실패). 실패한 장만 다시 만든다(최대 2회, 오탈자가 반복되면 주석 어절 수를 줄여 재시도).
5. **보고.** 장수·경로·각 장 용도·재생성 이력.

## Common Mistakes

| 실수 | 결과/해법 |
|---|---|
| 주석을 5어절+ 길게 | 한글 오탈자 확률 급증 → 2~4어절로 자르기 |
| composition에서 오리가 구경만 함 | 오리를 빼도 성립하는 그림 = 실패. 동작 주체로 다시 쓰기 |
| 한 장에 여러 메시지 | 설명서가 됨 → 장 분리 |
| labels에 영어/중국어 혼입 | 이미지에 그대로 새겨짐 → 한국어만 |
| CHARACTER 블록을 요약하거나 일부만 넣음 | 오리 얼굴이 매번 달라짐 → 통째로 넣는다 |
| 다른 일러스트 스킬의 프롬프트를 섞음 | 스타일이 무너짐 → PROMPT.md의 것만 사용 |
| 생성 후 QA 생략 | 오탈자·구도 붕괴가 그대로 납품됨 → Read 검사 필수 |
